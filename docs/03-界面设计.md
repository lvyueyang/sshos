# SSH 可视化终端管理工具 · 界面设计

本文档定义项目的全部页面设计规范。核心范式：**每个 SSH 连接 = 一个 OS 桌面 Tab**，用户在桌面内通过图标和窗口完成所有操作，而非传统多页面路由切换。技术实现见[技术架构](./02-技术架构.md)，技术决策见[决策记录](./04-决策记录.md)。

## 1 设计总则

### 1.1 设计理念

本工具的核心定位是**"远程 Linux 桌面外壳"**。用户像操作本地操作系统一样操作 SSH 连接的 Linux 服务器——侧栏管理连接列表，点击连接即打开一个 OS 桌面 Tab，桌面上有图标、状态卡片和任务栏，双击图标弹出应用窗口。
参考体验：Windows 桌面 + Ubuntu GNOME + VS Code 的多 Tab 管理，但比三者更强调"一个连接 = 一台完整操作系统"的整体感。

### 1.2 色彩系统（明暗双主题）

采用 **GitHub 配色基底**（暗色 / 亮色两套 token），以终端绿色作为主交互色，蓝色作为次要信息色。MVP 支持 **light / dark 两档**切换（默认 dark），通过 shadcn `.dark` class 策略切换，CSS 变量按 `:root`（light）/ `.dark`（dark）双值声明。

## 2 全局布局

### 2.1 整体架构

应用采用**侧栏 + 桌面 Tab**双区域结构。左侧固定侧栏管理 SSH 连接列表，右侧主区域为 Tab 栏 + 桌面内容区。每个 SSH 连接成功后打开一个独立 Tab，Tab 内渲染一个完整的仿 OS 桌面环境。

> **布局尺寸**：侧栏 240px（可折叠为 56px） · Tab 栏 36px · 桌面区域 flex-1

### 2.2 侧栏设计

侧栏是 SSH 连接管理器，采用行业通用的分组树形结构。从上到下分为四个区域：

- **Logo 区**（顶部 48px）：应用 Logo + 名称
- **搜索框**：实时过滤连接列表，支持名称/IP/标签搜索
- **连接树**：按分组展示连接列表，支持折叠/展开
- **底部操作区**：新建连接按钮 + 设置齿轮

### 2.3 侧栏连接树设计

连接以分组形式组织。每个分组显示为可折叠的标题行，包含分组名称和连接计数徽标。分组下的连接项显示：状态指示灯（8px 圆点）、连接名称、IP 地址缩略。

| 状态 | 指示灯 | 说明 |
| --- | --- | --- |
| 在线 | `--accent` 绿色实心圆 | SSH 会话活跃 |
| 离线 | `--muted` 灰色实心圆 | 未连接或已断开 |
| 连接中 | `--warn` 黄色脉冲动画 | 正在建立 SSH 连接 |
| 异常 | `--danger` 红色实心圆 | 连接失败或认证错误 |

> **侧栏交互**：默认展开 240px，快捷键 `Cmd/Ctrl+B` 切换折叠为 56px 图标态。连接项 hover 显示连接/编辑/删除图标按钮。**点击连接项**：未打开 → 新建 Tab 连接；已打开 → 切换聚焦到已有 Tab，不重复新建。右键连接项弹出上下文菜单：连接、复制连接、编辑、复制连接信息、移动到分组、删除。分组右键菜单：重命名、添加连接、删除分组。

### 2.4 连接分组装饰

分组支持自定义颜色标签（左侧 3px 色条），便于视觉区分。默认提供三个分组色：Production 红色、Development 蓝色、Personal 绿色。用户可自定义分组名和颜色。分组标题行右侧显示连接计数徽标，格式为 `N`。

### 2.5 Tab 栏设计

**一个连接只对应一个 Tab**，一一对应，不出现同一连接的多个桌面。重复打开同一连接（侧栏连接项、历史项、`ssh://` Deep Link）只会切换聚焦到已有 Tab，不新建。

每个已打开的 SSH 桌面会话在 Tab 栏显示为一个 Tab。Tab 包含：连接状态指示灯（6px 圆点）+ 连接名称 + 关闭按钮。活跃 Tab 底部有 2px accent 绿色下划线。支持拖拽排序和右键菜单（关闭其他 / 关闭右侧 / 复制连接信息）。关闭有运行中窗口的 Tab 时弹确认框。确需"同一台机器独立多开"时，通过连接项右键「复制连接」生成指向同一主机的新配置。

### 2.6 路由骨架

路由极简化，不做多页面路由切换。整个应用是**单页面应用（SPA）**结构，业务 RPC 走 SFn，流式/下载/健康检查走 Server Route：

```text
packages/web/src/
├─ routes/                 # 仅剩 App Shell + 首页 + api（无功能页面路由）
│  ├─ __root.tsx           # App Shell（侧栏 + Tab栏）
│  ├─ index.tsx            # 空白首页 / 最近连接
│  └─ api/                 # Server Route（流式/下载/health）
├─ apps/                   # 桌面应用插件包（terminal / files / monitor / clock / ai）
├─ app-framework/          # App 插件框架（manifest / context / 生命周期分发）
├─ components/             # 通用桌面组件（Sidebar / Desktop / Taskbar / Window）
├─ stores/                 # Zustand 桌面 UI 状态（窗口 / Tab / 焦点）
└─ middleware/             # SFn 中间件（policy-engine / audit-log）
```

> **核心原则**：路由不承载功能页面。所有远程操作通过 SFn（`createServerFn`）完成，流式输出通过 Server Route（`server.handlers` 返回 `Response(ReadableStream)`）完成；SFn 就近平级放在消费它的桌面应用目录（`apps/<app>/<app>.functions.ts`）。桌面窗口管理是纯客户端状态，不走服务端。

## 3 桌面系统

桌面是每个 SSH 连接 Tab 的核心内容区域。用户连接成功后看到一个仿 OS 桌面，包含桌面图标、状态卡片和任务栏。所有操作在这个桌面内通过窗口完成。

### 3.1 连接模型

一个 Tab = 一条 SSH 连接。桌面内所有窗口（终端、文件管理、监控、AI）共享同一条 SSH 连接，通过 ssh2 的多 channel 复用机制实现：

```text
Tab "web-01" (一个 SSH 连接)
│
├─ SSH Connection (ssh2.Client)
│   ├─ Channel 1: PTY ──→ 终端窗口 #1
│   ├─ Channel 2: PTY ──→ 终端窗口 #2
│   ├─ Channel 3: PTY ──→ 终端窗口 #3
│   ├─ SFTP Subsystem ──→ 文件管理窗口
│   ├─ exec Channel ──→ 系统监控（周期性 top/df/free）
│   └─ exec Channel ──→ AI 命令执行
│
└─ 连接生命周期 = Tab 生命周期
```

| 维度 | 共享连接（本方案） | 每窗口独立连接 |
| --- | --- | --- |
| 认证开销 | 一次 TCP+SSH 握手+认证 | 每开一个终端都重来一遍 |
| 资源占用 | 1 条 TCP 连接 + N 个 channel | N 条 TCP 连接 |
| SFTP 路径跟随 | 天然可行，同一文件系统上下文 | 需要额外同步机制 |
| AI 获取终端上下文 | 同连接，可直接读取当前目录和历史 | 跨连接，需 IPC |
| 断线影响 | 全部窗口一起断（有重连覆盖层） | 只有该窗口断 |
| 打开新终端速度 | 毫秒级（开 channel 即可） | 秒级（重新握手） |

ssh2 库原生支持在一条连接上复用多个 channel（PTY channel、exec channel、subsystem），这正是 SSH 协议的设计意图。

#### 连接生命周期

| 事件 | 动作 |
| --- | --- |
| 打开 Tab | 建立 SSH 连接，认证完成后渲染桌面 |
| 打开终端窗口 | 在共享连接上创建新 PTY channel |
| 打开文件管理 | 在共享连接上开启 SFTP subsystem |
| 关闭终端窗口 | 关闭对应 PTY channel，连接保持 |
| 关闭 Tab | 关闭所有 channel → 断开 SSH 连接 |
| SSH 断线 | Tab 内所有窗口显示重连覆盖层，指数退避重连 |

> **桌面状态卡片的角色**：桌面上的状态卡片是 monitor 应用的 `panel` surface，实时显示这条共享连接的资源使用情况（CPU / 内存 / 磁盘，见 §3.4），是 Tab 级别的资源监控。

### 3.2 桌面布局

桌面区域使用 `--desktop-bg` 渐变背景，从上到下分为三层：

- **图标网格层**：桌面左侧/区域排列应用图标，**只有声明 `window` surface 的应用才有桌面图标**，仿 Windows/Ubuntu 桌面
- **面板层**：桌面右上角等固定槽位（panel slot），承载 `panel` surface 的自启面板（如系统状态卡片）
- **任务栏**：底部 40px 高，仿 Windows 任务栏，两侧为 `statusbar` surface 槽位

### 3.3 桌面图标

桌面图标以网格排列（每列 72px 宽），每个图标包含 36x36px 图标图片 + 12px 文字标签。图标背景根据类型有不同的色系区分。图标只对应 `window` surface 的应用；`panel` / `statusbar` 类应用无图标，自启或通过面板/状态栏启用。

| 图标 | 色系 | 双击行为 |
| --- | --- | --- |
| Terminal | 终端绿色边框 | 弹出终端窗口 |
| Files | 蓝色边框 | 弹出文件管理窗口 |
| Monitor | 青色边框 | 弹出系统监控窗口 |
| AI | 紫色边框 | 弹出 AI 面板窗口 |

> **图标交互**：单击选中（紫色高亮边框 + 半透明背景），双击打开窗口。右键弹出菜单：打开、在终端中打开、查看属性。桌面空白区右键：刷新、排列图标、新建快捷方式、桌面设置。

### 3.4 状态卡片（panel surface）

桌面右上角浮动的实时状态卡片是 **monitor 应用的 `panel` surface**（自启、无图标），与 §7 系统监控窗口（monitor 的 `window` surface）共用同一份 metrics 能力。卡片通过 `metricsStreamSFn`（SFn 流式）每 2 秒推送数据，背景半透明 + 模糊滤镜，宽 180px。

| 卡片 | 主数值 | 进度条 | 告警阈值 |
| --- | --- | --- | --- |
| CPU | 百分比 + 核心数 | 绿色进度条 | >80% 变黄 / >95% 变红 |
| Memory | 已用 / 总量 | 紫色进度条 | >85% 变黄 / >95% 变红 |
| Disk | 已用 / 总量 | 黄色进度条 | >85% 变黄 / >95% 变红 |

### 3.5 任务栏（statusbar surface）

桌面底部 40px 高的任务栏，背景为半透明黑 + 模糊滤镜。从左到右分为：启动按钮、应用快捷区、statusbar 槽位、系统托盘。任务栏两侧为 `statusbar` surface 的槽位（left / center / right），自启应用常驻于此（如时钟）。

| 区域 | 内容 | 交互 |
| --- | --- | --- |
| 启动按钮 | 32x32 紫色方块 ⊞ 图标 | 点击展开应用列表（仿 Start Menu） |
| 分隔线 | 1px 竖线 | — |
| 应用快捷区 | 已打开窗口的图标，底部 2px 蓝条表示运行中 | 单击切换窗口聚焦/最小化 |
| statusbar 槽位 | 自启 statusbar 应用（时钟等） | 点击触发对应 app 交互 |
| 系统托盘 | 连接状态 + 主机信息 | 点击连接状态展开断开/重连菜单 |

### 3.6 窗口管理器

桌面内的窗口管理器负责所有应用窗口的创建、聚焦、拖拽、调整大小、最小化、最大化。窗口状态由 Zustand store 管理（`src/stores/windows.ts`），不经过 SFn。

| 操作 | 行为 | 快捷键 |
| --- | --- | --- |
| 拖拽标题栏 | 移动窗口位置 | — |
| 拖拽边缘 | 调整窗口大小 | — |
| 标题栏双击 | 最大化/还原 | — |
| 最小化按钮 | 收起到任务栏 | — |
| 关闭按钮 | 销毁窗口 | — |
| 点击窗口 | 聚焦到顶层 | — |
| 任务栏点击 | 切换聚焦/最小化 | — |
| 关闭窗口 | 有运行中进程时弹确认 | — |

> **窗口状态**：每个窗口维护 z-index（聚焦时置顶）、position（x/y）、size（width/height）、minimized（布尔）、maximized（布尔）。同一应用可多开窗口。窗口标题栏高度 32px，内容区最小 400x300px。

## 4 连接管理（侧栏）

连接管理位于侧栏，是用户进入应用后的首要交互区域。目标是让用户在 **10 秒内**完成一次新连接的创建和连接。

### 4.1 新建/编辑连接表单

点击侧栏底部的"新建连接"按钮，以**右抽屉**形式从右侧滑入，宽度 420px，遮罩层 60% 不透明度。

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| 连接名称 | text | 是 | 2-30 字符，唯一 |
| 主机地址 | text | 是 | IP 或域名格式 |
| 端口 | number | 是 | 1-65535，默认 22 |
| 用户名 | text | 是 | 非空 |
| 认证方式 | select | 是 | 密码 / 私钥（粘贴）/ 系统密钥 / SSH Agent |
| 私钥内容 | textarea | 条件 | 选择「私钥（粘贴）」时填写，明文入库（D23） |
| 系统密钥路径 | file picker | 条件 | 选择「系统密钥」时自动扫描 `~/.ssh/` 以下拉选择 |
| 密码 | password | 条件 | 非空 |
| 分组 | select | 否 | 选择已有或新建分组 |
| AI 操作开关 | toggle | 否 | — |
| 生产环境标记 | toggle | 否 | 影响 Policy Engine 规则集 |

### 4.2 连接测试反馈

点击"测试连接"后，按钮变为 loading 态，**5 秒超时**。结果以横幅显示在表单底部：

- **成功**：绿色横幅 "连接成功 — 服务器: Ubuntu 22.04 LTS"
- **失败**：红色横幅 "连接失败 — Authentication failed (publickey)"
- **超时**：黄色横幅 "连接超时 — 请检查网络和防火墙设置"

### 4.3 连接成功后的流程

```text
用户点击连接项
  -> 该连接已在某个 Tab 打开？
     |-- 是 -> 切换聚焦到已有 Tab，流程结束
     `-- 否 -> SSH 握手 + 认证
  -> 成功后：
    1. Tab 栏新建一个 Tab
    2. Tab 内渲染 Desktop 组件
    3. 桌面状态卡片开始推送 SFn 监控数据
    4. 用户双击桌面图标打开窗口
  -> 失败后：
    1. 侧栏连接项指示灯变红
    2. 弹出错误提示
```

### 4.4 空状态

> 首次使用（无任何已保存连接）时，侧栏连接树区域显示一个虚线边框的引导卡片，内含 `+` 图标 + "添加你的第一个连接" + 副文字 "支持密钥和密码认证"。点击后直接打开新建连接抽屉。

### 4.5 连接历史

侧栏底部显示最近连接历史列表（最多 50 条），按使用频率排序。点击历史项可直接发起连接。历史记录入库为每次连接一条（`connection_history` 表，含连接时长），UI 展示时按连接去重、更新访问时间后按使用频率排序。历史列表与书签分组树并列展示，通过侧栏顶部 Tab 切换：「书签」和「历史」。

### 4.6 Deep Link 支持

支持 `ssh://user@host:port` 协议链接，从浏览器或其他应用点击 ssh 链接可直接唤起应用并打开连接。Electron 壳注册协议处理器，捕获后聚焦窗口；**冷启动深链经 URL 参数 `?deeplink=` 带给渲染层**（决策记录 D21，壳的本地职责，不经过服务端 API），渲染层解析后命中已保存连接则连接（聚焦已有 Tab），否则预填新建连接抽屉。连接成功后自动在桌面 Tab 中打开终端窗口。

## 5 终端应用

终端是桌面上的核心应用窗口。基于 `xterm.js` 渲染，通过 `ptyStreamSFn`（SFn 流式）消费 PTY 输出。双击桌面 Terminal 图标弹出终端窗口。

### 5.1 终端窗口配置

| 属性 | 值 | 说明 |
| --- | --- | --- |
| 窗口默认尺寸 | 640x400 | 可拖拽调整大小 |
| 字体 | JetBrainsMono | 等宽，支持 CJK 宽字符 |
| 字号 | 14px | 可通过 `Cmd/Ctrl+/-` 调整 |
| 光标 | block | 闪烁动画 |
| 滚动 | 10000 行缓冲 | 滚轮平滑滚动 |
| 选中 | 鼠标拖选 | 自动复制到剪贴板 |
| 主题 | Monokai（默认），WebGL 渲染 | 可在窗口设置中切换 |

### 5.2 窗口内状态栏

终端窗口底部有一个 **28px 高**的状态栏，分三段显示信息：

| 左侧 | 中间 | 右侧 |
| --- | --- | --- |
| 连接状态指示灯 + Connected/Disconnected | 延迟（绿色 200ms） | 编码 UTF-8 · 80x24 |

### 5.3 多终端窗口

同一桌面内可打开多个终端窗口，每个窗口独立维护 PTY 会话。双击桌面 Terminal 图标即新建一个终端窗口。窗口标题显示连接名 + 窗口序号（如 "web-02 - Terminal #1"）。

- 新建终端窗口：双击桌面 Terminal 图标，或任务栏启动菜单
- 关闭终端窗口：关闭按钮，有运行中进程时弹确认框
- 切换窗口：点击任务栏图标或点击窗口
- **清除终端**：`Cmd/Ctrl+K`，清空当前终端屏幕内容

### 5.4 xterm.js 插件体系

借鉴 electerm 的深度定制方案，终端不只用裸 xterm.js，而是搭配官方和自定义插件构建完整体验：

| 插件 | 来源 | 功能 |
| --- | --- | --- |
| `@xterm/addon-webgl` | 官方 | WebGL 渲染加速，大量输出时不卡顿 |
| `@xterm/addon-fit` | 官方 | 自适应终端尺寸，窗口拖拽时自动 resize |
| `@xterm/addon-search` | 官方 | 终端内搜索，支持正则/大小写/全词匹配 |
| `@xterm/addon-web-links` | 官方 | URL 链接可点击 |
| `@xterm/addon-unicode11` | 官方 | Unicode 11 支持，CJK 宽字符正确渲染 |
| `@xterm/addon-image` | 官方 | iTerm2 图片协议，终端内显示图片 |
| CommandTrackerAddon | 自定义（借鉴 electerm） | 追踪用户执行的命令，配合 AI 审计日志 |
| KeywordHighlighterAddon | 自定义（借鉴 electerm） | 正则匹配高亮输出，快速定位 error/warning |
| Osc52Addon | 自定义（借鉴 electerm） | OSC52 剪贴板协议，远程终端操作本地剪贴板 |

### 5.5 Shell 集成

借鉴 electerm 的 shell 集成方案，连接建立后自动检测远程 shell 类型（bash/zsh/fish），注入集成命令实现：

- **SFTP 路径跟随**：终端 cd 到某目录时，文件管理窗口自动同步到该路径
- **命令提示**：基于历史命令提供上下键补全建议
- **当前路径获取**：AI 面板可获取终端当前工作目录，提供上下文

> **MVP 边界**：Shell 集成的「命令提示（历史补全）」依赖远程 shell 注入，风险高，列为后续迭代；SFTP 路径跟随与当前路径获取的实现载体见技术架构 §5.6。

### 5.6 终端内文件传输

支持 Zmodem/Trzsz 协议，用户在终端内直接使用 `rz`/`sz` 命令传输文件，弹出传输进度 UI。兼容 tmux 环境（Trzsz 方案）。`trzsz` 依赖包待 W0 确认，MVP 以拖拽上传（§5.7）为主要传输方式。

### 5.7 拖拽文件到终端

将本地文件拖拽到终端窗口区域时，显示拖放高亮区并弹出选择：上传到远程当前目录 / 输入文件路径到终端。拖放上传走 SFTP 通道，不阻塞终端输入。

### 5.8 批量输入

借鉴 electerm 的批量输入功能。用户可选中多个终端窗口，然后输入命令同时广播到所有选中的终端。适用于批量运维场景（如同时重启多个服务）。选中状态通过任务栏图标视觉反馈（紫色边框）。实现载体：`sendInputSFn` 支持 `sessionIds` 批量广播（技术架构 §5.6），属后续迭代。

### 5.9 终端搜索栏

快捷键 `Cmd/Ctrl+F` 在终端窗口底部弹出搜索栏。支持正则表达式、大小写敏感、全词匹配三种模式。匹配结果高亮，支持上一个/下一个导航。搜索范围覆盖 10000 行滚动缓冲区。

### 5.10 双主题系统

借鉴 electerm 将**终端配色**和**UI 配色**分离的设计：

- **终端主题**：ANSI 16 色 + 前景 + 背景 + 光标色，独立于 UI 主题。默认 Monokai，可在窗口设置中切换。支持 iTerm 主题导入
- **UI 主题**：应用整体配色，**light / dark 两档**（默认 dark，GitHub Dark 基底）。切换入口在设置面板，全局持久化到 `setting` 表（key = `appearance.theme`）；与终端主题相互独立、可任意组合（如 dark UI + 任意终端主题）

终端窗口的选中背景色通过混合算法（blendSelectionOverBackground）动态计算，确保在任何终端主题下选中态都清晰可辨。

### 5.11 断线重连

SSH 连接断开时终端窗口显示半透明覆盖层，自动尝试重连（最多 3 次，间隔 2/4/8 秒指数退避）。重连期间终端窗口保持上次输出内容，覆盖层显示"Reconnecting... (attempt 2/3)"。重连成功后恢复 PTY 会话；失败后覆盖层变为"连接已断开"+ 手动重连按钮。

## 8 AI 面板应用

AI 面板是本工具区别于传统 SSH 客户端的核心差异化功能。用户通过自然语言操作远程系统，所有 AI 生成的命令经过 Policy Engine 安全拦截。双击桌面 AI 图标弹出 AI 面板窗口。

### 8.1 窗口结构

AI 面板窗口默认宽度 420px，高度自适应桌面区域。窗口从上到下分为：标题栏（AI 助手 + 连接名）、消息列表区域（flex-1 滚动）、底部输入区。

### 8.2 消息气泡设计

| 角色 | 对齐 | 背景 | 圆角 |
| --- | --- | --- | --- |
| AI (assistant) | 左对齐 | bg2 | 左上 0 / 其余 12px |
| 用户 (user) | 右对齐 | rgba(63,185,80,0.1) | 右上 0 / 其余 12px |
| 系统提示 | 居中 | 透明 | — |

### 8.3 命令预览卡片

当 AI 要执行 shell 命令时，在 AI 消息气泡内嵌入一个命令预览卡片。卡片包含：工具名 + 命令类型标签、等宽字体代码块、Policy Engine 判定结果状态标签、操作按钮。

### 8.4 Policy Engine 视觉反馈

| 级别 | 卡片左边框 | 状态标签 | 按钮 |
| --- | --- | --- | --- |
| **safe** | accent 绿色 3px | 安全 — 只读操作 | [执行] |
| **review** | warn 黄色 3px | 需要审批 — 删除操作 | [拒绝] [批准执行] |
| **block** | danger 红色 3px | 已拦截 — 危险命令 | 无执行按钮，显示拦截原因 |

### 8.5 审批流程交互

```text
用户发送请求
  -> AI 生成命令 + tool_call -> 调 execCommandSFn
  -> Policy Engine 中间件分类（server 权威判定）
    |-- safe   -> 命令卡片显示绿色，用户点击 [执行] 放行
    |-- review -> 中间件登记挂起，抛 ApprovalRequiredError(requestId)
    |          -> 命令卡片显示黄色，显示 [拒绝] [批准执行]
    |          -> 用户点击 [批准执行] -> 调 approvalSFn(requestId, approved) 重放执行
    |          -> 用户点击 [拒绝]     -> 调 approvalSFn(requestId, rejected) 丢弃
    |          -> 结果返回给 AI -> AI 告知用户执行结果
    `-- block  -> 中间件直接抛错，命令卡片显示红色 + 拦截原因，无执行按钮
               -> AI 收到 block 结果 -> AI 告知用户命令被拦截
```

### 8.6 输入区设计

底部输入区包含：多行 textarea（placeholder "输入消息或命令..."，`Enter` 发送，`Shift+Enter` 换行）、附件按钮（可附加文件截图供 AI 分析）、历史按钮（展开审计日志列表）、发送按钮（accent 绿色背景）。

### 8.8 流式渲染

AI 回复通过 `aiChatSFn`（SFn 流式）的 `ReadableStream<AiTextDelta>` 增量流推送，客户端 `AiPanel` 调用后逐块读取 `text-delta`（`@tanstack/ai-react` 的 `useChat` 未采用，见决策记录技术验证记录）。打字效果为**逐字符渲染**，每 30ms 一个 token，与 ChatGPT 体验一致。流式过程中发送按钮变为"停止生成"按钮。
