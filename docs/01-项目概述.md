# SSH 可视化终端管理工具 · 项目概述

开源 · 非商业 · 像操作系统一样操作 SSH 连接的 Linux · AI 原生集成。

## 1 项目定位

把 SSH 终端从"命令行-only"升级成"可视化操作系统式"的交互体验——SSH 是底层驱动，类 OS 界面是外壳，AI 是让它真正像"操作系统"的大脑。

本项目的核心愿景是**远程 Linux 的桌面外壳**：通过纯 SSH 协议、零 agent，把远程服务器的文件、进程、软件、Docker 以桌面隐喻的方式可视化呈现。用户像操作本地电脑一样操作远程 Linux，AI 作为"第二消费者"接入同一套读写网关，提供理解、诊断、命令生成能力。

## 2 MVP 范围

**现在做：**

- **Electron 桌面应用**——Chromium 渲染 + xterm.js 终端，三平台一致体验
- **SSH 终端**——PTY 流式交互，多标签、多窗口
- **SFTP 文件管理**——目录浏览、上传/下载、编辑
- **系统状态监控**——CPU/内存/磁盘/进程实时仪表盘
- **连接管理**——密钥/密码认证、连接配置持久化
- **AI 集成（L1 起步）**——嵌入 Pi SDK，策略引擎就位，读优先

**未来畅想（不在 MVP 内）：**

- headless 服务模式——core 独立运行，浏览器自托管访问
- AI L2/L3——多步智能体自主执行、跨会话记忆与规划（W3 已交付"自然语言→命令，带人工审批"，见 §5 W3）

**既定路线（MVP 后交付，非畅想）：**

- WebDAV 个人云同步——多设备同步连接书签/快速命令/终端主题（详见[技术架构 §4.9](./02-技术架构.md)）

## 3 交互范式

**一个 SSH 连接 = 一个 OS 桌面 Tab。** 桌面内通过图标、窗口、任务栏完成所有操作，不做多页面路由切换（详见[界面设计](./03-界面设计.md)）。

## 4 架构铁律

无论桌面还是纯 web 服务模式，**renderer 永远不直连 Electron 的 ipcMain**。渲染层走 react-start 暴露的本地 HTTP API（localhost 回环），通信全部由 TanStack Start 体系承载。**服务模式已落地（决策记录 D21）**：web 包可独立启动（`node .output/server/index.mjs`），Electron 桌面端退化为纯浏览器壳；认证走「启动密码登录签发 JWT」，凭据明文存储（D23）。

## 5 实施路线

分四周交付，每周一个可验证的里程碑。所有通信走 TanStack Start 体系，无需 WebSocket、Hono 或独立网关。

### W0 — 流式 spike（✅ 已完成）

**目标**：验证全案最大不确定性——Server Route 流式 / ai-react 流式在 Electron 环境的可行性。

**交付物**：

- Server Route `api/pty.$sessionId.tsx` 返回 `ReadableStream`，客户端 fetch 消费，验证 PTY 输出延迟 < 100ms
- `@tanstack/ai-react` 0.19 `useChat` + connection adapter 实际 API 核对
- Pi SDK 可编程入口（`Pi` 类的 `stream`/`registerTool`）API 核对
- `node:sqlite` 在目标 Electron 版本可用性验证

**验证标准**：三条流式通道（PTY/监控/AI）跑通，输出可落 xterm.js；记录 API 签名差异并回填文档。

> **完成记录**：PTY 流（Server Route ReadableStream）实测首包 2-3ms、命令完整回显 104ms；metrics 流每 2s 一条 NDJSON、首包 0ms；Pi SDK 0.84.2 API 实测定稿（`createAgentSession` / `defineTool` / `session.subscribe`）；验证结论回填 `docs/04-决策记录.md` 技术验证记录与待验证清单。

### W1 — SSH 连接与终端流（✅ 已完成）

**目标**：用户能保存连接配置、建立 SSH 会话、在 xterm.js 中交互操作远程终端。

**交付物**：

- 连接管理：增删改查 SSH 配置，凭据明文存储（D23）
- `connectSFn`：建立 SSH 连接，返回 sessionId
- Server Route `api/pty.$sessionId.tsx`：ReadableStream 推送 PTY 输出
- `sendInputSFn`：POST 发送键盘输入（客户端输入队列串行化，防快速打字乱序）
- `resizePtySFn`：POST 调整终端尺寸
- Terminal 组件：xterm.js + `fetch` 消费 PTY 流
- Policy Engine v1：block 级规则（rm -rf /、mkfs、dd）

**验证标准**：中文输入无乱码，Ctrl+C / Ctrl+D 响应正常，多标签页独立会话不串流。

> **完成记录**：连接增改/测试/保存、桌面 Tab 打开、xterm 挂载、键盘输入→PTY→命令执行→输出回流全链路经 build 产物实测通过（连接 Docker 测试机 `localhost:2222`，`echo sshos-w1` 完整回显）。生产构建修复了三个框架级问题（产物引用 dev client、ssh2 CJS `__dirname` 报错、启动未迁移），详见 `docs/04-决策记录.md` 技术验证记录。dev 模式 SFn 全挂为已知问题（vite 8.2.1 SSR module runner 兼容 gap），W1 验证与 Electron 生产模式统一走 build 产物；中文输入 / Ctrl+C / 多标签独立会话依赖 core 集成测试与架构决策（Electron 自带 Chromium），工具级实测受限。

### W2 — SFTP 文件管理与监控（✅ 已完成）

**目标**：文件浏览器 + 流式下载上传 + 实时系统监控。

**交付物**：

- `sftpListSFn` / `sftpStatSFn` / `sftpMkdirSFn` / `sftpDeleteSFn` / `sftpRenameSFn`（删除 / 重命名挂 Policy Engine 路径分类）
- Server Route `api/sftp/download`：ReadableStream 流式下载（RFC 6266/5987 双态文件名）
- Server Route `api/sftp/upload`：流式上传（body 直写远程路径，XHR 进度条）
- Server Route `api/metrics.$sessionId`：每 2s 推送 CPU / 内存 / 磁盘 / 网络指标
- 文件管理器组件：目录浏览 + 双击进入 + 右键菜单（下载/重命名/删除）+ 上传进度队列 + 新建目录
- 监控仪表盘组件：实时指标卡片 + CPU/内存趋势折线（SVG）
- 审批 UI：`listPendingApprovalsSFn` + 通用 ApprovalDialog（review 级文件操作弹窗，批准后经 approvalSFn 重放执行，无绕过路径）
- Policy Engine v2：review 级规则（rm、chmod、systemctl stop、生产追加 restart/管道脚本/`/var/lib`）——P 阶段已落地，W2 经删除/重命名审批链路实测

**验证标准**：100MB 文件下载不卡 UI，监控指标刷新间隔 ≤ 2s，文件操作经 Policy Engine 校验。

> **完成记录**：build 产物实测通过——目录浏览、上传（UI + curl，上传/下载内容一致、中文完整）、删除 → review 审批弹窗 → 批准重放执行（审计落 `review/approved/success`）、监控仪表盘实时指标（CPU/内存/磁盘/网络）。上传 route 用 `stream/promises` pipeline 修复（SFTP 写流 `finish` 事件不总是触发）；路由文件命名须用子目录 `sftp/download`（点号不为 tanstack 路径分隔符）；审批 UI 为 W2 补全（此前仅服务端 registry + approvalSFn）。Docker 测试机 `test` 用户对 `/`、`/home` 无写权限，写操作实测在 `/tmp` 进行。

### W3 — AI 集成与安全闭环（✅ 已完成）

**目标**：嵌入 Pi SDK，用户可通过自然语言操作远程系统，所有 AI 命令经策略引擎拦截。

**交付物**：

- Server Route `api/ai.chat`：SSE 流式对话（Pi 事件 → text-delta 帧）
- `ai/pi-agent.ts`：Pi Agent 封装（createAgentSession + defineTool，shell / file_read / list_dir 工具）
- `apps/ai/exec.service.ts`：命令执行服务（classifyCommand 策略 + 审计 + 审批登记），AI 工具与 execCommandSFn 共用
- `apps/ai/AiPanel.tsx`：对话面板（SSE 消费 + 审批轮询弹窗）
- Policy：execCommandSFn / AI 工具命令全部经策略引擎（block 拦截 / review 审批 / safe 执行），审计完整
- promptGuard：`guardChatInput`（system 角色拒绝 + 注入模式检测）供 Server Route 与 SFn 共用
- 审批弹窗：复用 W2 的 ApprovalDialog + `listPendingApprovalsSFn` 轮询

**验证标准**：AI 生成的 `rm -rf` 被 block 拦截，`rm file` 触发 review 审批，审计日志完整可查。

> **完成记录**：build 产物实测通过——AI 对话 SSE 流（中文正常）、`pwd`（safe）执行并审计 `safe/executed`、`rm -rf /` 被 block（审计 `block/blocked`）、`date`（review）触发审批弹窗 → 批准后重放执行（审计 `review/approved`）。调试中发现并记录：SFn 返回 Response 在序列化层被吞（200 空 body，改用 Server Route）；Pi SDK 打包后 createAgentSession 挂起（external）；`noTools:"all"` 会禁用自定义工具（须 `"builtin"`）；Pi 文本增量在 `message_update.assistantMessageEvent`（text_delta / text_end）；execCommandSFn 服务端调用会 fnId 查找失败（AI 工具走 exec.service 的 execWithPolicy）。**已知行为**：模型执行工具后不一定生成自然语言总结（取决于模型），核心安全链路不受影响。

> **完成记录**：`pack:dir` 本地打包实测通过——`@electron/get` 版本不匹配（app-builder-lib 声明 ^3 但代码用 v5 API）经 `pnpm-workspace.yaml` overrides 修复；server 的 external 运行时依赖（ssh2 / pi-coding-agent）经 `prepare-server.mjs` 闭包分发到 `.output/server/node_modules`，打包后随 `extraResources` 分发，隔离目录全部 chunk 解析通过，并经打包产物真实 SSH 连接 Docker 测试机成功；`@sshos/web` 移至 desktop devDependencies 后 asar 从 113M 瘦身至 1.1M；图标由 `scripts/generate-icon.mjs` 零依赖生成（1024 PNG，electron-builder 转 .icns/.ico）。凭据加密接线（D18）见前置依赖记录与 docs/02 §4.6（D23 已改为明文存储，加密逻辑移除）。
