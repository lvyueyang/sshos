# SSH 可视化终端管理工具 · 项目概述

开源 · 非商业 · 像操作系统一样操作 SSH 连接的 Linux · AI 原生集成。

## 1 项目定位

把 SSH 终端从"命令行-only"升级成"可视化操作系统式"的交互体验——SSH 是底层驱动，类 OS 界面是外壳，AI 是让它真正像"操作系统"的大脑。

本项目的核心愿景是**远程 Linux 的桌面外壳**：通过纯 SSH 协议、零 agent，把远程服务器的文件、进程、软件、Docker 以桌面隐喻的方式可视化呈现。用户像操作本地电脑一样操作远程 Linux，AI 作为"第二消费者"接入同一套读写网关，提供理解、诊断、命令生成能力。

## 2 MVP 范围

**现在做：**

- **Electron 桌面应用**——Chromium 渲染 + xterm.js 终端，三平台一致体验
- **SSH 终端**——PTY 流式交互，多标签、多窗口
- **SFTP 文件管理**——目录浏览、上传/下载、编辑
- **系统状态监控**——CPU/内存/磁盘/进程实时仪表盘
- **连接管理**——密钥/密码认证、连接配置持久化
- **AI 集成（L1 起步）**——嵌入 Pi SDK，策略引擎就位，读优先

**未来畅想（不在 MVP 内）：**

- headless 服务模式——core 独立运行，浏览器自托管访问
- AI L2/L3——多步智能体自主执行、跨会话记忆与规划（W3 已交付"自然语言→命令，带人工审批"，见 §5 W3）

**既定路线（MVP 后交付，非畅想）：**

- WebDAV 个人云同步——多设备同步连接书签/快速命令/终端主题（详见[技术架构 §4.9](./02-技术架构.md)）

## 3 交互范式

**一个 SSH 连接 = 一个 OS 桌面 Tab。** 桌面内通过图标、窗口、任务栏完成所有操作，不做多页面路由切换（详见[界面设计](./03-界面设计.md)）。

## 4 架构铁律

无论桌面还是未来的服务模式，**renderer 永远不直连 Electron 的 ipcMain**。渲染层走 react-start 暴露的本地 HTTP API（localhost 回环），通信全部由 TanStack Start 体系承载。这一条不增加开发量，却是未来"长出服务模式"的唯一桥梁——只要守住它，服务模式是免费送的。

## 5 实施路线

分四周交付，每周一个可验证的里程碑。所有通信走 TanStack Start 体系，无需 WebSocket、Hono 或独立网关。

### W0 — 流式 spike

**目标**：验证全案最大不确定性——Server Route 流式 / ai-react 流式在 Electron 环境的可行性。

**交付物**：

- Server Route `api/pty.$sessionId.tsx` 返回 `ReadableStream`，客户端 fetch 消费，验证 PTY 输出延迟 < 100ms
- `@tanstack/ai-react` 0.19 `useChat` + connection adapter 实际 API 核对
- Pi SDK 可编程入口（`Pi` 类的 `stream`/`registerTool`）API 核对
- `node:sqlite` 在目标 Electron 版本可用性验证

**验证标准**：三条流式通道（PTY/监控/AI）跑通，输出可落 xterm.js；记录 API 签名差异并回填文档。

### W1 — SSH 连接与终端流

**目标**：用户能保存连接配置、建立 SSH 会话、在 xterm.js 中交互操作远程终端。

**交付物**：

- 连接管理：增删改查 SSH 配置，凭据 safeStorage 加密存储
- `connectSFn`：建立 SSH 连接，返回 sessionId
- Server Route `api/pty.$sessionId.tsx`：ReadableStream 推送 PTY 输出
- `sendInputSFn`：POST 发送键盘输入
- `resizePtySFn`：POST 调整终端尺寸
- Terminal 组件：xterm.js + `fetch` 消费 PTY 流
- Policy Engine v1：block 级规则（rm -rf /、mkfs、dd）

**验证标准**：中文输入无乱码，Ctrl+C / Ctrl+D 响应正常，多标签页独立会话不串流。

### W2 — SFTP 文件管理与监控

**目标**：文件浏览器 + 流式下载上传 + 实时系统监控。

**交付物**：

- `sftpListSFn` / `sftpStatSFn` / `sftpMkdirSFn` / `sftpDeleteSFn`
- Server Route `api/sftp.download.tsx`：ReadableStream 流式下载，带进度条
- Server Route `api/sftp.upload.tsx`：ReadableStream 流式上传
- Server Route `api/metrics.$sessionId.tsx`：每 2s 推送 CPU / 内存 / 磁盘 / 网络指标
- 文件管理器组件：树形目录浏览 + 拖拽上传 + 右键菜单
- 监控仪表盘组件：实时折线图（CPU / 内存 / 网络 IO）
- Policy Engine v2：新增 review 级规则（rm、chmod、systemctl stop）

**验证标准**：100MB 文件下载不卡 UI，监控指标刷新间隔 ≤ 2s，文件操作经 Policy Engine 校验。

### W3 — AI 集成与安全闭环

**目标**：嵌入 Pi SDK，用户可通过自然语言操作远程系统，所有 AI 命令经策略引擎拦截。

**交付物**：

- `aiChatSFn`：SSE 流式（形态由 W0 spike 定稿）
- 客户端 `useChat` 集成 @tanstack/ai-react
- Pi Agent 封装：shell / file_read / file_write / sftp 工具映射到 SFn
- Policy Engine v3：Prompt 注入检测（promptGuard 中间件）+ 系统提示词隔离
- 审批弹窗组件：review 级命令需人工确认
- 审计日志中间件 + BatchWriter：记录所有 SFn 调用（用户、时间、命令、结果）

**验证标准**：AI 生成的 `rm -rf` 被 block 拦截，`rm file` 触发 review 审批，审计日志完整可查。

### W4 — 打包与发布

**目标**：Electron 桌面应用打包发布，开源仓库初始化。

**交付物**：

- Electron Builder 配置：macOS (dmg) / Windows (nsis) / Linux (AppImage)
- 自动更新：electron-updater 接入 GitHub Releases
- 用户引导：首次启动连接配置向导
- 开源仓库：README、CONTRIBUTING、LICENSE (MIT)、CI (GitHub Actions)
- 文档：架构说明 + SFn 函数清单 + Policy Engine 规则集

**验证标准**：三平台安装包可用，自动更新链路通，README 包含构建和开发指南。
