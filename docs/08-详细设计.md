# SSH 可视化终端管理工具 · 详细设计

本文档承接[技术架构](./02-技术架构.md)，存放架构下方的接口清单、数据模型与关键实现契约。代码仓库是最终事实来源，本文档为设计与约定记录。

## 1 分层约定

三层代码分离，适用于所有业务模块：

| 文件 | 职责 | 规则 |
| --- | --- | --- |
| `*.server.ts` | 纯 SSH 逻辑（连接、PTY、SFTP 操作） | 禁止使用 SFn 后缀；可被 `.functions.ts` 和其他 `.server.ts` 引用；路由/组件禁止直接 import |
| `*.functions.ts` | SFn 包装器 + 流式构造 | 每个 `createServerFn` 变量必须以 `SFn` 结尾；不直接操作 SSH |
| `*.schemas.ts` | Zod schema 定义 | 入参出参类型契约，服务层用 `z.infer` 派生类型 |

> **Server Route 例外**：下载/流式/health 等 API 路由（`routes/api/*.tsx`）允许通过 `server.handlers` 直接写服务端 handler 并引用 `.server.ts`——这是 TanStack Start Server Route 的合法形态，与 SFn 是两套并存范式，不适用"SFn 必须放 `.functions.ts`"规则。

**SFn 命名与放置**：SFn 就近定义在消费它的应用目录（`apps/<app>/<app>.functions.ts`），变量名统一 `SFn` 后缀；连接 / 分组 / 设置等全局数据统一在 `services/settings/connections/settings.functions.ts`。

| `resizePtySFn` | POST | 调整终端尺寸 | 同上 |

| `listPendingApprovalsSFn` | GET | 列出某会话挂起审批（AI 面板审批弹窗消费） | 同上 |
| `sftpListSFn` | GET | 列出远程目录 | `apps/files/` |
| `sftpStatSFn` | GET | 获取文件元信息 | 同上 |
| `sftpMkdirSFn` | POST | 创建远程目录（低风险新建，不挂策略） | 同上 |
| `sftpDeleteSFn` | POST | 删除远程文件 / 目录（用户手动操作，**不挂策略**） | 同上 |
| `sftpRenameSFn` | POST | 重命名 / 移动（用户手动操作，**不挂策略**，SFTP rename 原语覆盖两者） | 同上 |

```typescript
export const log = sqliteTable('log', {

// App 设置（键值对）

  key: text('key').primaryKey(),

// 每连接配置（键值）：App 会话状态与桌面布局快照（key = app.<id>.state / desktop.layout），

export const connectionSetting = sqliteTable('connection_setting', {
```

### 4.1 数据库连接

```typescript
// src/db/index.ts
import path from 'node:path'
import { DatabaseSync } from 'node:sqlite'
import { drizzle } from 'drizzle-orm/node-sqlite'
import * as schema from './schema'
import { getDataDir } from './lib/paths'

const sqlite = new DatabaseSync(
  path.join(getDataDir(), 'ssh-os.db'),   // 数据目录约定见技术架构 §4（SSHOS_DATA_DIR 可覆盖）
  { enableForeignKeyConstraints: true }
)
sqlite.exec('PRAGMA journal_mode = WAL')  // 并发读不阻塞写
sqlite.exec('PRAGMA foreign_keys = ON')

export const db = drizzle({ client: sqlite })
```

> **关键陷阱**：node:sqlite 的**事务回调必须同步**（同 better-sqlite3）；普通查询经 drizzle 驱动返回 Promise，服务层统一 `await db.select()` 风格。

## 5 运行时日志（Pino）

调试和排查用的运行时日志不进 SQLite，使用 `pino` 写本地文件，按天轮转，超期自动清理。日志文件存储在 `{dataDir}/logs/` 目录下，命名 `YYYY-MM-DD.log`；超过 `LOG_RETENTION_DAYS`（默认 7 天）的旧文件在启动 / 跨天滚动时自动删除（`lib/logger/logger.server.ts` 的 `DailyRotatingStream` + `cleanupExpiredLogs`）。

```typescript
// src/logger.ts
import pino from 'pino'
import path from 'node:path'
import { getDataDir } from './lib/paths'

const logFile = path.join(getDataDir(), 'logs', 'app.log')

export const logger = pino({
  level: process.env.NODE_ENV === 'development' ? 'debug' : 'info',
  transport: {
    target: 'pino/file',
    options: { destination: logFile, mkdir: true },
  },
})

logger.info({ host, port }, 'SSH connecting')
logger.error({ err, sessionId }, 'SSH connection failed')
logger.debug({ channelId, bytes }, 'PTY data received')
```

| 层 | 存储 | 记录内容 | 用途 |
| --- | --- | --- | --- |
| 结构化日志 | SQLite `log` 表 | AI 审计、终端命令、Policy Engine 决策 | UI 展示、查询过滤、审计面板 |
| 运行时日志 | 本地文件（Pino） | SSH 握手、SFTP 传输、异常堆栈、SFn 调用 | 开发调试、问题排查 |

> 高频审计写入用审计日志专属 BatchWriter（`services/audit/audit-writer.server.ts` 的 `auditLogWriter`，底层为 `lib/batch-writer` 通用 `BatchWriter<T>`）：定时/定量批量 INSERT + 容量上限 + 进程退出时强制刷新，避免每条命令落库拖慢 PTY 吞吐。

## 6 App 插件契约

### 6.1 Manifest 类型

```typescript
// packages/web/src/app-framework/types.ts
type Capability = 'pty' | 'sftp' | 'exec' | 'ai' | 'metrics'
type PanelSlot = 'top-left' | 'top-right'        // 桌面面板槽位

interface ContextMenuContribution {
  id: string                  // 唯一标识，处理器据此绑定
  target: ContextMenuTarget
  label: string               // 显示文案（i18n key 或字面量）
  icon?: string
  group: string               // 分组：open / manage / transfer / custom
  order?: number              // 组内排序（默认 0）

interface AppManifest {
  id: string
  title: string
  icon?: string
  capabilities: Capability[]     // 能力声明，框架据此裁剪 ctx.ssh 暴露面
  singleton?: boolean            // window 是否单实例（默认 false，可多开）

  id: string                    // 工具标识，默认探测目标（command -v <id>）
  label: string
  neededFor: string[]           // 依赖此工具的功能 id
  fallback?: string             // 无此工具时的降级行为说明（UI hint）
```

### 6.3 生命周期

```text
registered
  → 连接成功 / statusbar 自启 → onCreate(ctx)
  → 有保存状态 → onRestore(state)          # 还原上次
  → running
  → Tab 关闭 → onSave() 收状态 → onStop()   # 实例销毁、状态保留
  → Tab 重建 → onCreate → onRestore(上次状态)
  → 系统退出 → onShutdown('systemExit' | 'tabClose' | 'userClose')
```

- `onCreate(ctx)`：初始化，返回 Disposable（对齐 VS Code 订阅模式，dispose 时清理）
- `onRestore(state)`：有上次保存状态时调用，还原布局与内容
- `onSave()`：Tab 关闭 / 系统退出前调用，返回可序列化 JSON 状态
- `onShutdown(reason)`：实例被系统关闭时调用，`reason` 区分是系统退出、Tab 关闭还是用户手动关闭

```typescript
// apps/clock/app.ts —— statusbar app 示例（自启、无图标、常驻）
```

### 6.4 上下文菜单

声明式 manifest + `setup(ctx)` 绑定处理器（对齐 VS Code `contributes.contextMenus`，决策记录「右键菜单框架」）：

```typescript
// 示例：第三方 app 给文件添加「上传到对象存储」
export const manifest: AppManifest = {
  id: 'uploader',
  title: '对象存储上传',
  capabilities: ['sftp'],
  contributes: {
    contextMenus: [
      { id: 'uploader.push', target: 'file', label: '上传到对象存储', group: 'custom', order: 10 },
      { id: 'uploader.pullDir', target: 'folder', label: '同步该目录到云端', group: 'custom', order: 20 },
    ],
  },
}

export function setup(ctx: AppContext) {
  const disposables = [
    ctx.menus.registerHandler('uploader.push', async ({ session, items }) => {
      return pushToCloudSFn({ data: { sessionId: session.sessionId, paths: items.map(i => i.path) } })
    }),
    ctx.menus.registerHandler('uploader.pullDir', async ({ session, path }) => {
      return syncDirSFn({ data: { sessionId: session.sessionId, path } })
    }),
  ]
  return { dispose: () => disposables.forEach((d) => d()) }
}
```

**上下文对象**：

```typescript
interface ContextMenuContext {
  target: 'file' | 'folder'       // 实际作用对象
  session: { connectionId: number; sessionId: string }
  path: string                    // 当前目录
  items: FileInfo[]               // 选中的文件/文件夹（1+）
  selectionCount: number
}
```

**分组与排序**：菜单项按 `group` 分组渲染，内置项在前、app 贡献项以分隔线隔开。内置分组：`open`（打开、在终端中打开）/ `manage`（重命名、删除、复制路径、查看属性）/ `transfer`（下载、上传到…、粘贴）；`custom` 为各 app 贡献项（按 app 聚合）。同一 `group` 内按 `order` 升序。

**渲染流程**：

```text
文件/文件夹右键
  → files 窗口收集本 Tab 运行中 app 的 manifest.contributes.contextMenus
  → 过滤 when 条件（folder-only / selection-count / 路径 glob）
  → 校验能力：未声明 sftp 能力的 app 贡献被丢弃
  → 按 group/order 分组排序，内置项 + 各 app「应用」分组渲染
  → 点击项 → 查找 setup 注册的 handler → 注入 ContextMenuContext → 执行
```

**约束**：处理器内动作一律走 SFn，写操作（删除/覆盖等）经 Policy Engine（review → 审批），无绕过路径；注册返回 Disposable，app `onStop()` 自动回收；未运行 app 的贡献项不出现；`id` 全局唯一，重复注册以先注册者为准并告警。

> **当前实现边界**：files 应用的下载 / 重命名 / 删除等**内置项**由 `FileManagerMenu` 组件硬编码渲染，贡献点框架供第三方 app 声明与注册；内置 app 自身不再把内置操作声明为贡献项，避免与内置项重复渲染。

## 7 策略引擎契约

### 7.1 execWithPolicy

命令分类与执行统一收敛在 `services/ssh/command/exec.service.ts` 的 `execWithPolicy`（AI 工具、`execCommandSFn`、安装引导共用；服务端直接调用，不走 SFn 中间件——`execCommandSFn` 未在 server manifest 注册时服务端调用会 fnId 查找失败，见决策记录技术验证记录）：

```typescript
// packages/web/src/services/ssh/command/exec.service.ts
import { classifyCommand } from "#/services/policy/classifier";
import { ApprovalRequiredError, approvalRegistry, PolicyError } from "#/services/ai/approval/registry";
import { auditLogWriter, type LogAction, type LogResult } from "#/services/audit/audit-writer.server";
import { execCommand, resolveIsProduction } from "#/services/ssh/connection/ssh.server";

export async function execWithPolicy(sessionId: string, command: string): Promise<string> {
  const isProduction = await resolveIsProduction(sessionId);
  const verdict = classifyCommand({ command }, { isProduction });

  // block 级 — 记审计后直接拒绝
  if (verdict.level === "block") {
    writeAudit(sessionId, command, "block", "blocked", "failure", verdict.reason);
    throw new PolicyError(verdict);
  }
  // review 级 — 登记挂起，抛 ApprovalRequiredError 等待人工审批后重放
  if (verdict.level === "review") {
    writeAudit(sessionId, command, "review", "pending_approval", "failure", verdict.reason);
    const requestId = approvalRegistry.register({
      fnName: "execCommand",
      data: { sessionId, command },
      sessionId,
      reason: verdict.reason,
      replay: () => execDirect(sessionId, command), // 批准后直接执行，不再过策略
    });
    throw new ApprovalRequiredError(requestId, verdict.reason);
  }
  // safe 级 — 直接执行
  const stdout = await execDirect(sessionId, command);
  writeAudit(sessionId, command, "safe", "executed", "success");
  return stdout;
}
```

### 7.2 分类器

分类器位于 `services/policy`：`classifyCommand`（shell 文本）与 `classifyFileOperation`（SFTP 路径）。三段式判定：**黑名单 block → 只读白名单 safe → 默认 review**。规则定义在 `rules.ts`（仅维护 block 黑名单），白名单单一来源在 classifier 的 `READ_COMMANDS`，不逐条枚举写操作规则。

```typescript
// packages/web/src/services/policy/classifier.ts
import { getRules, getPathRules } from "./rules";
import type { Verdict } from "./types";

// 读命令白名单：支持裸命令（ls / df / ps…）与带参数两种形态，
// 用「命令 + 空白或结尾」匹配，避免裸命令被误判为写操作；
// `command -v` 为远程工具探测专用（只读、固定命令），仅放行精确形态
const READ_COMMANDS = [
  /^(?:ls|cat|grep|head|tail|df|free|ps|top|pwd)(?:\s|$)/,
  /^command\s+-v(?:\s|$)/,
];

function classifyByReadWrite(cmd: string): Verdict {
  const isRead = READ_COMMANDS.some((re) => re.test(cmd));
  if (!isRead) return { level: "review", reason: "write / unknown command" };
  // 只读命令带输出重定向（> / >> / 2>）实为写操作，降级 review
  if (/>>?|2>>?/.test(cmd)) return { level: "review", reason: "read command with redirection" };
  // 拼接 / 管道符可把只读命令扩展成任意命令（如 `ls; curl x | bash`），一并降级 review
  if (/[;|&]|\$\(|`/.test(cmd)) return { level: "review", reason: "read command with chaining" };
  return { level: "safe", reason: "read-only command" };
}

export function classifyCommand(data: unknown, opts?: { isProduction?: boolean }): Verdict {
  const cmd = extractCommand(data);
  for (const rule of getRules({ isProduction: opts?.isProduction })) {
    if (rule.pattern.test(cmd)) return { level: "block", reason: rule.description };
  }
  return classifyByReadWrite(cmd);
}
```

### 8.1 对话流与错误帧协议

`aiChatSFn`（`services/ai/chat/chat.functions.ts`）挂 `promptGuardMiddleware`，handler 动态 import `services/ai/chat/chat.server.ts` 的 `createAiChatStream`（避免服务端依赖进入 client bundle），返回增量流：

```typescript
// packages/web/src/services/ai/chat/chat.server.ts
export type AiStreamChunk =
  | { type: 'text-delta'; delta: string }   // 正常增量
  | { type: 'error'; message: string }      // 终止帧：未配置模型 / prompt 失败 / 空响应

export async function createAiChatStream(
  sessionId: string,
  messages: AiChatMessage[],           // role 仅 user / assistant（system 由 guardChatInput 拒绝）
): Promise<ReadableStream<AiStreamChunk>> {
  guardChatInput(messages)             // 注入检测：system 角色 + 注入模式（中间件之外的双保险）

  const tools: AgentTools = { /* execCommand 经 execWithPolicy / readFile / listDir */ }

  const agent = await createPiAgent(tools)
  // session.subscribe 事件流 → controller.enqueue({ type: 'text-delta', delta })
  if (!agent.modelFallbackMessage) {
    void agent.prompt(messages.map((m) => m.content).join('\n')).catch(fail)
  }
  return stream
}
```

**错误帧协议（不吞错）**：`AiStreamChunk` 为判别联合——`text-delta` 正常增量，`error` 服务端终止帧。三条失败路径必须发 `error` 帧而非静默关流：① `modelFallbackMessage`（未配置可用模型）；② `agent.prompt` reject（原实现只 `closeStream()`，导致"发送消息无任何提示"）；③ `agent_settled` 时全程无文本。**裁决时点**：`turn_end` / `agent_end` 每次尝试都会触发（`willRetry=true` 表示 pi 将重试），必须在 `agent_settled`（整个 agent 运行结束的可靠信号）裁决空响应；成功且有文本时在最终 `agent_end(willRetry=false)` 提前关流防挂起。**自定义端点指引**：pi 对 OpenAI 兼容端点强制 `stream:true` SSE 流式请求，非流式响应报 `Stream ended without finish_reason` 并重试后空返回——空响应错误帧会透出该真实原因并提示检查 baseUrl（需以 `/v1` 结尾）、API 类型、SSE 流式支持。客户端收到 `error` 帧展示 `[错误] <message>`；流正常结束但无内容时兜底提示「模型未返回任何内容」。

### 8.3 Pi Agent 封装

API 已按 0.84.2 实测定稿（spike 验证）：无 `Pi` 类 / `registerTool` / `stream()`。SDK 模式入口为 `createAgentSession`，自定义工具用 `defineTool`（**TypeBox schema + `execute` 方法**），事件流经 `session.subscribe(listener)`。工具调用链：`session.prompt(text)` → 事件流 `tool_call` → `execute` 返回 `AgentToolResult`。

```typescript
// packages/web/src/services/ai/pi-agent.ts
import { createAgentSession, defineTool } from '@earendil-works/pi-coding-agent'
import { Type } from 'typebox'

export interface AgentTools {
  execCommand(command: string): Promise<{ isError: boolean; content: string }>
  readFile(path: string): Promise<{ isError: boolean; content: string }>
  listDir(path: string): Promise<{ isError: boolean; content: string }>
}

export async function createPiAgent(tools: AgentTools) {
  const shellTool = defineTool({
    name: 'shell',
    label: 'Shell',
    description: '在远程会话执行一条 shell 命令（非交互式）。命令会经过安全策略引擎校验，被拦截或需审批时返回错误说明。',
    parameters: Type.Object({ command: Type.String() }),
    execute: async (_toolCallId, params: { command: string }) => toToolResult(await tools.execCommand(params.command)),
  })

  // noTools "all" 会连自定义工具一起禁用；"builtin" 禁用内置（read/bash/edit/write）但保留 customTools
  const { session, modelFallbackMessage } = await createAgentSession({
    noTools: 'builtin',
    customTools: [shellTool, fileReadTool, listDirTool],
  })
  return { session, modelFallbackMessage, prompt: session.prompt.bind(session), subscribe: session.subscribe.bind(session) }
}
```

### 9.2 WebDAV 同步

| 维度 | 设计 |
| --- | --- |
| 同步粒度 | 整库文件同步（ssh-os.db），不拆表增量 |
| 触发时机 | 手动同步 + 应用退出时自动同步 + 启动时检测远端更新 |
| 冲突处理 | 时间戳比较：远端更新时间 > 本地 → 拉取；本地更新时间 > 远端 → 推送；无法判断 → 弹窗让用户选择 |
| 敏感数据 | 密码/私钥为明文存储，整库同步即同步凭据；同步目标应视为可信环境 |
| 同步范围 | 仅同步 ssh-os.db 主文件，WAL/SHM 文件不同步（推送前 checkpoint 合并） |

```text
推送（Push）：
  1. SQLite checkpoint → 将 WAL 合并到主 db 文件
  2. 记录本地 lastModified 时间戳
  3. PUT ssh-os.db 到 WebDAV 服务器
  4. 在远端写入元数据文件 ssh-os.db.meta（含时间戳、设备名）

拉取（Pull）：
  1. GET ssh-os.db.meta → 比较远端时间戳 vs 本地时间戳
  2. 若远端更新 → 先本地 checkpoint，把 WAL 合并到主 db 文件（避免本地未落盘数据在替换时丢失）
  3. GET ssh-os.db 到临时文件，校验 SQLite 完整性（PRAGMA integrity_check）
  4. 关闭当前主 DB 连接 → 替换本地 db 文件 → 重新打开连接（Windows 上替换被占用的文件会失败）

冲突解决：
  1. 比较本地 lastModified 和远端 meta 时间戳
  2. 本地更新 → 提示用户：推送覆盖远端 / 拉取覆盖本地 / 取消
  3. 用户选择后执行对应操作
```

**设置界面**：服务器地址、用户名、密码、自动同步开关、设备名；「测试连接」验证可达性；底部状态栏显示同步状态（已同步 / 同步中 / 同步失败 / 远端有更新）。

## 10 通信实现

### 10.1 PTY 通道（WebSocket）

PTY 是唯一需要全双工持续双向的场景。浏览器与 web 服务之间建立一条 WebSocket 连接承载 shell 双向数据流：

```text
客户端 Terminal                       web 服务端                     远程 shell（ssh2 PTY）
  xterm.js onData ──上行帧──▶ ┌──── WS 网关 ───────▶ PTY channel write ──▶ stdin
  xterm.js write  ◀──下行帧── │   （按 sessionId 绑定会话）
  resize 消息 ──────上行─────▶ └──────────────────── PTY resize
  Terminal.write ◀─输出流───── ◀──────────────────── stdout 数据
```

**协议要点**：

- **握手**：客户端先经 `ptyWsTicketSFn` 获取一次性握手票据（绑定 sessionId），随后以票据建立 WebSocket 连接；服务端按票据绑定到对应 PTY 会话并校验鉴权。
- **下行帧**（Server → Client）：`{ type: 'output', data }`——PTY 输出，客户端 `Decoder` 搬运进 `Terminal.write`。
- **上行帧**（Client → Server）：`{ type: 'input', data }`（键盘输入，仅 UTF-8 格式校验）、`{ type: 'resize', cols, rows }`。
- **生命周期**：连接断开自动清理会话绑定；`closePtySFn` 由终端窗口卸载时销毁 PTY，避免重开复用死 pty。
- **发射频率**：shell 高频输出逐帧下行，不做缓冲合并（保证低延迟；本机场景实测首包 < 5ms 级）。
